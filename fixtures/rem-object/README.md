# REM-OBJECT Vector Manifests

These JSON manifests pin the initial Section 13 values for the REM-OBJECT 1.0
positive vectors. The original core vectors were generated by the Remanence
reference implementation. The additional Section 13.1 plaintext-suite fixtures
were generated by the independent Python verifier first, then checked by
`crates/remanence-format/tests/rem_object_vectors.rs`, so the expanded suite does not
freeze a value produced only by the Rust implementation.

The independent Python verifier rebuilds the positive plaintext streams without
using the Remanence Rust crates. It opens current REM-OBJECT-TV-E2 and REM-OBJECT-TV-D1
envelopes with `kyber-py` ML-KEM-768, generic X25519, HKDF-SHA-256, and
ChaCha20-Poly1305 primitives. It verifies the recovered canonical bytes,
`plaintext_digest`, manifest bytes, and every regular-file digest.

The checked-in object-directory copies are current REM-ENCRYPT 1.0 X-Wing
envelopes. The Rust Reader and independent verifier both reject the permanently
reserved `wrap_suite = 0x01`, and the Sealer has no alternate emission mode.

The same verifier carries the Section 14 plaintext-interop gate:

```sh
python3 -m pip install -r tools/requirements-rem-object-independent.txt
python3 tools/verify_rem_object_vectors_independent.py --check-plaintext-interop
```

That command requires GNU tar, bsdtar, and Python `tarfile`, and extracts every
positive plaintext vector byte-identically, including REM-OBJECT-TV-P1, the plaintext
REM-OBJECT-TV-D1, and the additional REM-OBJECT 13.1 fixtures. In an environment where bsdtar
is not installed, `--allow-missing-bsdtar` runs the GNU tar and Python
`tarfile` portions while making the missing reader explicit.

`rem-object-tv-e2.json` records the fixed DEK, seeded HPKE entropy input, both
recipient keypairs as test material, and the complete derivation chain. The
publication builder's Rust export hook regenerates the X-Wing E2 and D1
envelopes twice, then the
independent Python verifier derives their 1216-byte public keys from the
32-byte seeds, opens every slot, and writes current derivation pins into the
temporary archive staging tree. The checked-in source fixtures carry the same
current pins.

Negative-vector manifests with `status: complete` enumerate the Section 13.6
negative families. The Rust negative-vector tests assert both the exact case
IDs and the mapped errors or acceptance outcome, so dropping or duplicating a
required case fails the fixture gate. The one-slot read-acceptance case records
the intentional policy asymmetry: Sealers default to at least two slots and
require an explicit opt-in to emit one; Readers accept any structurally valid
frame with at least one.
