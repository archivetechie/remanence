# Presence verdicts for Layer 5 wire fields whose zero value is the honest answer.
#
# One line per field:  <Message.field>  <reason the zero value is genuinely correct>
#
# This is a record of DECISIONS TAKEN, not a list of permitted exceptions. A field
# appears here because someone examined it and concluded that zero, empty or false
# is a truthful value for it — not because flattening it was convenient. The reason
# is written down so it can be argued with later.
#
# Every other field must be one of: declared `optional`, an enum carrying its own
# *_UNSPECIFIED = 0, a repeated field, or a submessage. Anything else reads as
# UNEXAMINED in `tools/wire_presence_census.py`, which is the honest state for a
# field nobody has yet considered.
#
# Nested message fields are written with their full path, e.g. Outer.Inner.field.
#
# The count of fields still UNEXAMINED is the work, and it is meant to be visible.
# It is not repeated here, because a hand-kept number rots: this line used to say
# 353 while the census said 252. Run `python3 tools/wire_presence_census.py` for
# the live figure, or count tools/wire-presence-baseline.txt.

WriteSession.body_format      resolved when the session opens -- the caller's, or the daemon default it declined to name -- so a session always has one

# Write-session lifecycle requests, decided 2026-08-06. The rule inverts for a
# request: the CALLER supplies the value, so a required parameter stays plain
# and an absent one is a rejected request, not an Option the server has to
# interpret. That is only true if the server actually rejects it, so each of
# these was read against its handler rather than assumed. Every session_id
# below reaches decode_uuid_bytes (lib.rs), which refuses anything that is not
# exactly 16 bytes -- empty included -- with INVALID_ARGUMENT.
CheckpointSessionRequest.session_id  refused by decode_uuid_bytes; you cannot checkpoint an unnamed session
CloseWriteSessionRequest.session_id  refused by decode_uuid_bytes
AbortWriteSessionRequest.session_id  refused by decode_uuid_bytes
GetWriteSessionRequest.session_id    refused by decode_uuid_bytes

# The append stream, decided 2026-08-06. Same rule as above, same method: read
# against the handler.
#
# caller_object_id is the one worth writing down at length, because the schema
# argues the other way and the schema loses. `objects.caller_object_id` is
# nullable and its index is partial on `is not null`, which reads as a column
# expecting absence -- so this field looks like it should be optional. It is
# not: an append that names no object is refused before any tape I/O, by
# rem-object layout admission ("caller_object_id must not be empty",
# remanence-format/src/layout.rs, surfaced as INVALID_ARGUMENT), and the body
# format's manifest requires the key outright (manifest.rs `required_text`).
# No writer in the tree produces a NULL caller_object_id. The nullable column
# is the thing that is out of step, not the wire field; recorded in STANDING
# rather than papered over here.
AppendObjectStart.session_id                  refused by decode_uuid_bytes
AppendObjectStart.caller_object_id            required; an unnamed object is refused at layout admission, so absence is a rejected request
AppendObjectStart.CallerMetadataEntry.key     a map entry exists because the caller inserted it; the key is what it inserted it under
AppendObjectStart.CallerMetadataEntry.value   an empty value is a value the caller chose to store, and a map has no third state
AppendObjectChunk.session_id                  refused by decode_uuid_bytes via ensure_same_session
AppendObjectChunk.data                        a chunk carries the bytes it carries; zero bytes is an empty chunk, never an unknown one
AppendObjectFinish.session_id                 refused by decode_uuid_bytes via ensure_same_session
